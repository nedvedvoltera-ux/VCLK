# Глоссарий проекта

Этот файл фиксирует термины UI/UX и сущности системы.
**Перед любой доработкой сверяйтесь с этим файлом**, чтобы не ломать принятую модель экранов и ролей.
При добавлении функции обновляйте также `FEATURE_CHECKLIST.md` и unit-тесты.

---

## Роли и доступы

### Администратор (`admin`)

- Полный доступ к планировщику: все встречи организации, пользователи, LDAP/SMTP, режим работы системы.
- Может создавать локальных пользователей с login (e-mail) + пароль.
- Может редактировать и удалять любую встречу, переносить события в календаре.

### Пользователь (`user`)

- Видит и планирует свои встречи и те, куда приглашён.
- Редактирует/удаляет только встречи, где он организатор.
- Не видит разделы «Пользователи», «Режим», LDAP, SMTP.

### Гость (внешний участник)

- Без учётной записи VCLK.
- Может войти только в **свободную комнату** (`/room` с произвольным кодом), если включён свободный режим.
- К запланированной встрече — через персональное приглашение (активация аккаунта) или после выдачи доступа организатором.

### Организатор встречи

- Пользователь, создавший запланированную встречу (`organizer_id`).
- Права на карточку: просмотр, правка, удаление, вложения, приглашения; перетаскивание в календаре.

## Экраны

### Dashboard (планировщик)

- Определение: основной UI после входа — обзор, календарь, пользователи (admin), интеграции.
- Технически: `DashboardApp`, путь `/` (и всё, кроме `/room` и `/invite/...`, пока нет токена комнаты).
- **Не запрашивает камеру/микрофон.** Медиа только в комнате ожидания и комнате общения.
- Чеклист: секции планировщика (P*).

### Обзор (dashboard home)

- Блок счётчиков (ближайшие / сегодня / роль).
- Список ближайших встреч: название текстом, описание со ссылками, вложения, действия «Открыть» / «Пригласить» / «Файл» / «Подключиться».
- Мини-календарь месяца.

### Календарь встреч

- FullCalendar: виды **месяц / неделя / день** (`dayGridMonth`, `timeGridWeek`, `timeGridDay`).
- Клик по событию → карточка встречи (режим просмотра).
- Перетаскивание события → подтверждение переноса (только организатор/admin).
- При выборе «неделя» / «день» открывается **текущая** неделя/день, не первая неделя месяца.

### Карточка встречи (просмотр / правка)

- **Просмотр:** тема, время, организатор, описание, участники, вложения, напоминание, запись.
- У организатора/admin в шапке: иконка карандаша (редактировать) и корзины (удалить с подтверждением).
- **Правка:** форма темы, описания, начала, времени окончания (тот же день), участников, вложений, напоминания, флага записи, **переключатель «Повторяющаяся встреча»** (период: каждый день / каждую неделю / каждый месяц, по умолчанию неделя).
- В просмотре повторяющейся встречи показывается строка «Повторяется: …».
- Создание новой — сразу форма «Запланировать встречу».

### Режим работы системы (admin → «Режим»)

- Два независимых переключателя (хотя бы один должен быть включён):
  - **Свободный режим** — произвольные комнаты по коду на `/room` для всех, включая гостей; API `POST /token`.
  - **Создание встреч через календарь** — планирование в dashboard; `POST /api/meetings`.
- У каждого переключателя кнопка «i» с описанием при наведении.
- Публично отдаётся в `GET /api/bootstrap` (`freeMode`, `calendarMode`).

### Вход в VCLK (auth)

- Локальный login: e-mail + пароль (мин. 10 символов).
- Опционально AD/LDAP.
- Первый запуск: создание администратора (`/api/setup`).
- При включённом свободном режиме — ссылка «войти в свободную комнату» без аккаунта.

### Комната ожидания

- Определение: UI перед входом, где пользователь проверяет камеру/микрофон, видит диагностику и подтверждает имя.
- Технически: путь `/room` (и `/room?meeting=<id>` для запланированной встречи), пока `token === null`.
- Здесь **единственное место до комнаты общения**, где включается превью камеры/микрофона (`getUserMedia`).
- Свободная комната: поля имя + код комнаты (если `freeMode`).
- Запланированная: имя из профиля, кнопка «Подключиться к встрече» → `POST /api/meetings/:id/join`.
- Чеклист: секция A.

### Комната общения

- Определение: интерактивная комната после входа, где участники обмениваются аудио/видео через LiveKit.
- Технически: экран внутри `LiveKitRoom` после получения токена.
- URL обычно остаётся `/room?...`; UI переключается состоянием `token`.
- Чеклист: секция B.

### Архив записей

- Определение: отдельная HTML-страница для просмотра сохранённых `.mp4` записей комнат.
- Технически: server-rendered UI в `server/index.js`, не React SPA.
- URL просмотра: `/recordings`
  - локально: `https://localhost:5173/recordings` (или `https://localhost:8443/recordings` в prod-compose)
  - прод-пример: `https://vclk.asntl.ru/recordings`
- Вход в архив: `/recordings/login` (логин/пароль из `RECORDINGS_VIEW_USER` / `RECORDINGS_VIEW_PASSWORD`).
- Чеклист: секция C.

- Определение: мини-версия видео участника в комнате общения.
- Элементы верстки:
  - Desktop focus-режим: блок миниатюр `meet-focus-thumbs`, элемент миниатюры `meet-thumb-button`.
  - Mobile для 2 участников: мини-превью `meet-mobile-self-preview`.

### Превью фото

- Определение: отображение фото участника при выключенной камере в комнате общения.
- Элемент верстки: `meet-avatar-overlay` (внутри `meet-participant-shell` / `lk-participant-tile`).

### Видео блок

- Определение: основной блок с видео участника.
- Элементы верстки:
  - Плитка участника: `meet-participant-shell` + `lk-participant-tile`.

### Активный видео блок

- Определение: выбранный видео блок в центре экрана, который сейчас показан пользователю.
- Элементы верстки:
  - Основная область в focus-режиме: `meet-focus-main`.
  - Активная плитка: `meet-main-tile`.

### Режим фокус

- Определение: раскладка desktop, где один крупный видео блок и полоса миниатюр.
- Переключение: меню ⚙ → «Вид: фокус».

### Режим сетка

- Определение: раскладка desktop с равными плитками участников (`GridLayout`).
- Переключение: меню ⚙ → «Вид: сетка 2x2».

### Панель участников

- Определение: боковой список участников комнаты с статусом «говорит» / «в сети».
- Элемент: `meet-participants-panel`.

### Чат комнаты

- Определение: обмен текстовыми сообщениями между участниками через data channel LiveKit.
- Элементы: `meet-chat-drawer`, ControlBar chat.

### Бейдж REC

- Определение: индикатор активной серверной записи комнаты в топбаре.
- Элемент: `meet-rec-badge`.

### Ссылка-приглашение

- Определение: URL для приглашения в комнату.
- Свободный режим: страница с `?room=...`.
- Календарь: `/room?meeting=<id>` или персональная ссылка `/invite/<token>`.

## Сущности и сервисы

### Токен доступа (JWT)

- Определение: краткоживущий ключ для входа участника в комнату LiveKit.
- Свободный режим: `POST /token` (тело: `room`, `username`, опционально `avatarUrl`) — только если `freeMode=true`, иначе 410.
- Запланированная встреча: `POST /api/meetings/:id/join` (сессия обязательна, проверка участника/организатора/admin).

### Аватар участника

- Определение: фото профиля (192×192 JPEG), снятое в комнате ожидания или загруженное как data URL.
- API: `POST /avatar`, `GET /avatar/:id`.
- В комнате: metadata участника (`avatarUrl`), оверлей при выключенной камере.

### Запись комнаты (Egress)

- Определение: серверная композитная запись комнаты в `.mp4` через LiveKit Egress.
- API: `/recording/start`, `/recording/stop`, `/recording/status`.
- Файл: `{slug-комнаты}-{timestamp}.mp4` в каталоге записей.
- Ручной старт/стоп в комнате общения (кнопка записи → `POST /recording/start` / `/stop`).
- Флаг встречи `recording_enabled` («Записывать встречу»): при **двух и более** участниках в комнате общения клиент один раз вызывает автостарт egress. Если флаг выключен — только ручная запись. Повторный старт блокируется сервером (`alreadyRunning`) и клиентским флагом попытки.

### Сессия архива записей

- Определение: cookie-сессия после логина на `/recordings/login` (HMAC, TTL 12ч).
- Env: `RECORDINGS_VIEW_USER`, `RECORDINGS_VIEW_PASSWORD`, `RECORDINGS_SESSION_SECRET`.

### Запланированная встреча

- Определение: сохранённая ВКС с темой, описанием, периодом, организатором, участниками, вложениями и стабильным `room_id` LiveKit (`vclk-…`).
- Доступ: администратор — все; пользователь — организованные и приглашённые.
- Удаление: мягкая отмена (`status=cancelled`), встреча пропадает из календаря и ближайших.

### Повторяющаяся встреча

- Определение: запланированная встреча с `recurrence` = `daily` / `weekly` / `monthly` (по умолчанию `none`). Повторяется **в то же время** (локальное время часового пояса встречи, сдвиг по летнему времени учитывается), с той же длительностью.
- **Одна запись на серию:** общие `id`, `room_id` (комната), ссылка `/room?meeting=<id>`, участники и вложения. Вхождения не хранятся, а раскладываются сервером в `GET /api/meetings` (`occurrence_key`, `series_starts_at`, `series_ends_at`); горизонт — ~400 дней вперёд, не более 1000 вхождений.
- Месячный повтор: если в месяце нет нужного числа (31-е), берётся последний день месяца.
- В календаре и списке отмечается значком «↻»; в «Ближайших встречах» серия показана один раз (ближайшее вхождение); перетаскивание в календаре для серий отключено.
- Правка любого вхождения меняет всю серию (время сдвигается на ту же разницу); удаление отменяет всю серию. Исключения/отмена одного вхождения не поддерживаются.
- Напоминание уходит перед каждым вхождением; `.ics` содержит `RRULE:FREQ=…`.

### Персональное приглашение

- Определение: одноразовая ссылка с ограниченным сроком действия для указанного e-mail.
- Действие: создаёт локальный аккаунт приглашённого либо ведёт к входу; дальше — комната ожидания встречи.

### Локальная учётная запись

- Определение: пользователь `auth_source=local` с e-mail (login) и `password_hash`.
- Создаётся админом в разделе «Пользователи» (пароль + повтор с живой проверкой совпадения) или через активацию приглашения / setup.

### Интеграции LDAP и SMTP

- LDAP/AD: проверяет корпоративную учётную запись; группа администраторов назначает роль `admin`.
- SMTP: доставляет приглашение и вложение `.ics`, совместимое с Outlook.
- Защита: Bind- и SMTP-пароли хранятся зашифрованными с `SETTINGS_ENCRYPTION_KEY`.

### Вложение встречи

- Определение: файл, прикреплённый организатором или администратором к конкретной ВКС.
- Ограничения: до 20 МБ, максимум 10 на встречу; допустимы PDF, Office, TXT/CSV и PNG/JPEG.
- Защита: права организатора/admin, cooldown между upload, проверка расширения/MIME; имена с кириллицей нормализуются при сохранении.

### Качество сети

- Определение: оценка downlink браузера для подсказки пользователю в комнате ожидания.
- Значения: `low` (<5 Мбит/с), `medium` (5–15), `high` (>15), `unknown`.

### Signaling proxy

- Определение: WebSocket-прокси nginx/vite `/livekit` → LiveKit `:7888`.
- Клиент подключается к `wss://<host>/livekit`.

### Демонстрация экрана

- Определение: публикация `Track.Source.ScreenShare`; в порядке треков имеет приоритет над камерой.

### Транскрипт записи

- Определение: текстовая расшифровка аудиодорожки `.mp4` записи комнаты.
- Артефакт: `{имя}.transcript.json` (+ `{имя}.transcript.txt`) рядом с записью.
- Движок: `faster-whisper` в контейнере `asr-worker` (сейчас CPU, `small` / int8).
- Запуск: автоматически после `/recording/stop`, либо кнопкой «Запустить» / «Перезапустить» в архиве.

### Саммари встречи

- Определение: краткое резюме транскрипта (темы, решения, задачи).
- Считается на **сетевой большой Qwen** по OpenAI-compatible API:
  - Base URL: `http://192.168.215.74:9080/v1`
  - Model: `Qwen/Qwen3.5-35B-A3B-FP8`
- В UI: вкладка «Саммари» в модальном окне транскрипта.

### Очередь транскрибации

- Определение: Redis-список (`transcription:jobs`), куда `server` кладёт задачи, а `asr-worker` забирает по одной (CPU concurrency=1).

### ASR worker

- Определение: Docker-сервис `asr-worker` (`asr/`), который делает ffmpeg → Whisper → HTTP summary к Qwen.

### Диаризация

- Определение: разделение реплик по спикерам. В v1 выключена (`diarization.enabled: false`, `speaker: null` в сегментах); планируется после переноса на GPU.

### Android-приложение

- Определение: нативный клиент VKS (`android/`, Kotlin + Jetpack Compose + LiveKit Android SDK), пакет `ru.asntl.vclk`, сборка `gradle :app:assembleDebug` → `android/app/build/outputs/apk/debug/app-debug.apk` (подпись debug-ключом).
- Первый запуск: экран «Адрес сервера» (`https://host`); адрес хранится на устройстве, сменить можно через меню профиля. Сессия — cookie `vclk_session`.
- Экраны повторяют веб: вход / первичная настройка, приглашение `/invite/:token`, Обзор, Календарь (месяц / неделя / день), карточка встречи (просмотр / правка / создание, повтор, вложения, напоминание, запись), комната ожидания, комната общения (фокус / сетка, участники, чат, демонстрация экрана, запись и автозапись, REC).
- Deep-link: `https://host/invite/…` и `https://host/room?meeting=…|room=…` открываются в приложении.
- Отличия от веба: нет перетаскивания встреч в календаре (перенос — через правку), нет разделов «Настройки» (пользователи, режим, интеграции), нет архива записей и транскриптов.
- Фото профиля в комнате ожидания — снимок системной камерой, обрезается до 192×192 JPEG, как в вебе.
