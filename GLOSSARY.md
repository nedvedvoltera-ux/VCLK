# Глоссарий проекта

Этот файл фиксирует термины UI/UX и сущности системы.
При добавлении функции обновляйте также `FEATURE_CHECKLIST.md` и unit-тесты.

---

## Экраны

### Комната ожидания

- Определение: UI перед входом, где пользователь проверяет камеру/микрофон, видит диагностику и вводит данные для входа.
- Технически: экран, который рендерится, пока `token === null`.
- URL: обычно `https://localhost:5173/` (или прод-домен) с query-параметрами комнаты, например `?room=demo-room`.
- Чеклист: секция A.

### Комната общения

- Определение: интерактивная комната после входа, где участники обмениваются аудио/видео потоками.
- Технически: экран внутри `LiveKitRoom`, который рендерится после получения токена.
- URL: тот же, что и до входа (UI переключается состоянием приложения, отдельного роутинга сейчас нет).
- Чеклист: секция B.

### Архив записей

- Определение: отдельная HTML-страница для просмотра сохранённых `.mp4` записей комнат.
- Технически: server-rendered UI в `server/index.js`, не React SPA.
- URL: `/recordings` (логин `/recordings/login`).
- Чеклист: секция C.

## Элементы комнаты общения

### Превью видео

- Определение: мини-версия видео участника в комнате общения.
- Элементы верстки:
  - Desktop focus-режим: блок миниатюр `meet-focus-thumbs`, элемент миниатюры `meet-thumb-button`.
  - Mobile для 2 участников: мини-превью `meet-mobile-self-preview`.

### Превью фото

- Определение: отображение фото участника при выключенной камере в комнате общения.
- Элемент верстки: `meet-avatar-overlay` (внутри `meet-participant-shell` / `lk-participant-tile`).

### Видео блок

- Определение: основной блок с видео участника.
- Элементы верстки:
  - Плитка участника: `meet-participant-shell` + `lk-participant-tile`.

### Активный видео блок

- Определение: выбранный видео блок в центре экрана, который сейчас показан пользователю.
- Элементы верстки:
  - Основная область в focus-режиме: `meet-focus-main`.
  - Активная плитка: `meet-main-tile`.

### Режим фокус

- Определение: раскладка desktop, где один крупный видео блок и полоса миниатюр.
- Переключение: меню ⚙ → «Вид: фокус».

### Режим сетка

- Определение: раскладка desktop с равными плитками участников (`GridLayout`).
- Переключение: меню ⚙ → «Вид: сетка 2x2».

### Панель участников

- Определение: боковой список участников комнаты с статусом «говорит» / «в сети».
- Элемент: `meet-participants-panel`.

### Чат комнаты

- Определение: обмен текстовыми сообщениями между участниками через data channel LiveKit.
- Элементы: `meet-chat-drawer`, ControlBar chat.

### Бейдж REC

- Определение: индикатор активной серверной записи комнаты в топбаре.
- Элемент: `meet-rec-badge`.

### Ссылка-приглашение

- Определение: URL текущей страницы с параметром `?room=...`, которым можно пригласить участника.
- Где: поле в комнате ожидания; кнопка «Копировать ссылку» в комнате общения.

## Сущности и сервисы

### Токен доступа (JWT)

- Определение: краткоживущий ключ для входа участника в комнату LiveKit.
- API: `POST /token` / `GET /token`.
- Поля запроса: `room`, `username`, опционально `avatarUrl`.

### Аватар участника

- Определение: фото профиля (192×192 JPEG), заснтое в комнате ожидания или загруженное как data URL.
- API: `POST /avatar`, `GET /avatar/:id`.
- В комнате: metadata участника (`avatarUrl`), оверлей при выключенной камере.

### Запись комнаты (Egress)

- Определение: серверная композитная запись комнаты в `.mp4` через LiveKit Egress.
- API: `/recording/start`, `/recording/stop`, `/recording/status`.
- Файл: `{slug-комнаты}-{timestamp}.mp4` в каталоге записей.

### Сессия архива записей

- Определение: cookie-сессия после логина на `/recordings/login` (HMAC, TTL 12ч).
- Env: `RECORDINGS_VIEW_USER`, `RECORDINGS_VIEW_PASSWORD`, `RECORDINGS_SESSION_SECRET`.

### Качество сети

- Определение: оценка downlink браузера для подсказки пользователю в комнате ожидания.
- Значения: `low` (<5 Мбит/с), `medium` (5–15), `high` (>15), `unknown`.

### Signaling proxy

- Определение: WebSocket-прокси nginx/vite `/livekit` → LiveKit `:7888`.
- Клиент подключается к `wss://<host>/livekit`.

### Демонстрация экрана

- Определение: публикация `Track.Source.ScreenShare`; в порядке треков имеет приоритет над камерой.

### Транскрипт записи

- Определение: текстовая расшифровка аудиодорожки `.mp4` записи комнаты.
- Артефакт: `{имя}.transcript.json` (+ `{имя}.transcript.txt`) рядом с записью.
- Движок: `faster-whisper` в контейнере `asr-worker` (сейчас CPU, `small` / int8).
- Запуск: автоматически после `/recording/stop`, либо кнопкой «Запустить» / «Перезапустить» в архиве.

### Саммари встречи

- Определение: краткое резюме транскрипта (темы, решения, задачи).
- Считается на **сетевой большой Qwen** по OpenAI-compatible API:
  - Base URL: `http://192.168.215.74:9080/v1`
  - Model: `Qwen/Qwen3.5-35B-A3B-FP8`
- В UI: вкладка «Саммари» в модальном окне транскрипта.

### Очередь транскрибации

- Определение: Redis-список (`transcription:jobs`), куда `server` кладёт задачи, а `asr-worker` забирает по одной (CPU concurrency=1).

### ASR worker

- Определение: Docker-сервис `asr-worker` (`asr/`), который делает ffmpeg → Whisper → HTTP summary к Qwen.

### Диаризация

- Определение: разделение реплик по спикерам. В v1 выключена (`diarization.enabled: false`, `speaker: null` в сегментах); планируется после переноса на GPU.

## Правило сопровождения

1. Новый термин / сущность → запись в этот файл.

3. Тестируемая логика → helper + unit-тест (`server/lib`, `web/src/lib`).
